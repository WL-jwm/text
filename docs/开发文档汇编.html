1.2 Bug 修复详情

B-01: comprehensiveAssessment 空指标值崩溃

文件：src/services/waterQuality.ts

触发条件：收到空 indicatorValues（{}）时，Math.max(...[]) 返回 -Infinity，WATER_CLASS_LABELS[-Infinity].description 崩溃。

生产触发场景：

  • 新建监测井尚未录入数据
  • 批量处理时个别井数据缺失
  • 数据导入失败导致 indicatorValues 为空

修复方案：空指标值时提前返回默认评价（class=1, label='无数据'）；正常路径增加 ?. 安全链。

影响：正常数据结果不变；空数据从崩溃变为容错。

B-02: classifyFactor 水质类别不累加

文件：src/utils/waterQualityCalculator.ts

触发条件：监测值同时超过多级标准限值，类别停滞在较低级别。示例：TDS 标准 I≤300、II≤500、III≤1000，实测值 800。

步骤800 > 限值?修复前修复后
检查 II 类(≤500)是设为 II 类（停滞）设为 III 类（累加）
检查 III 类(≤1000)否继续遍历break 停止
最终结果—II 类（误判）III 类（正确）

根因：原代码超过某类限值后设为当前类（cls）而非下一类，且不 break。

2.2 排查清单

A. 空集合崩溃（模式 A）

在以下操作前，确认集合是否可能为空：

Math.max(...arr)     // 空数组返回 -Infinity
Math.min(...arr)     // 空数组返回 Infinity
arr.reduce(fn, init) // 空数组无初始值时报错
arr[0]               // 空数组返回 undefined

排查问题：该数组是否可能为空？空数组时是否有默认值/提前返回？链式调用中每一步是否都有空值保护？对象属性访问是否用了 ?. 安全链？

B. 循环累加停滞（模式 B）

// 危险信号
for (const item of list) {
  if (condition) {
    result = item;      // 设为当前项而非下一项
  }
}

排查问题：循环变量是推进到"下一项"还是停留在"当前项"？满足条件后是否应该 break？最后一次迭代是否产生正确的边界结果？是否有测试验证多级累加场景？

C. 边界条件过严（模式 C）

if (lines.length < 2) return empty;  // 阈值 2 是否合理？
if (data.length < 3) return null;    // 阈值 3 是否合理？

排查问题：该阈值的最小合理值是多少？边界值各应返回什么？拒绝输入时是否丢失了有价值的中间结果？

D. 测试数据失配（模式 D）

时间相关：时间戳是硬编码还是动态计算？硬编码时间戳是否超过过滤窗口？测试是否在任何日期都能通过？

Mock 数据与逻辑匹配：Mock 数据是否满足被测函数的所有前置条件？条件分支的每个路径是否都有对应的 mock 数据？

断言方向：比较操作符方向是否正确？预期值是否与注释/文档一致？

function processData(items: Item[]) {
  if (items.length === 0) {
    return { class: 0, label: '无数据' };   // 提前返回默认值
  }
  const max = Math.max(...items.map(i => i.value));
  return { class: max, label: LABELS[max]?.name ?? '未知' };  // 安全链
}

循环累加模板

// 修复前
for (const level of LEVELS) {
  if (value > level.threshold) {
    result = level;           // 设为当前级，不累加
  }
}
// 修复后
for (let i = 0; i < LEVELS.length; i++) {
  if (value > LEVELS[i].threshold) {
    if (i + 1 < LEVELS.length) {
      result = LEVELS[i + 1];  // 设为下一级，推进累加
    } else {

  } else {
    break;                     // 未超过 → 停止
  }
}

第三部分 前端命名规范

适用范围：hebei-groundwater-platform（React 18 + TypeScript + Zustand + Three.js）
目的：统一命名规则，保证代码可读性与可检索性

3.1 文件命名

类型规则示例说明
组件PascalCase.tsxWellNetworkPanel.tsx组件文件用大写驼峰，与导出的组件名一致
HookuseCamelCase.tsuseWaterBalance.tsuse 前缀，小写驼峰
服务/工具camelCase.tswaterQuality.ts小写驼峰，体现模块职责
测试文件名.test.ts(x)waterQuality.test.ts与源文件同名 + .test 后缀
类型xxx.types.tswaterQuality.types.ts仅含类型的文件用 .types.ts 后缀

3.2 组件命名（PascalCase）

// 正确：PascalCase 函数组件
function WellNetworkPanel() { ... }
const SpatialMap = () => { ... };
// 错误
function wellNetworkPanel() { ... }   // 首字母小写
说明：React 约定组件名必须大写开头，否则 JSX 会将其当作原生 DOM 标签导致渲染错误。

3.3 Hook 命名（use + camelCase）

// 正确
function useWaterBalance() { ... }
// 错误
function getWaterData() { ... }    // 不以 use 开头，绕过 eslint 检查
说明：use 前缀是 React Hook 的强制约定，eslint 依赖此前缀校验 Hook 调用规则。

3.4 状态变量命名（camelCase）

// 正确：名词，表达状态含义
const wellList = useMemo(() => ..., []);
const [selectedWellId, setSelectedWellId] = useState<string | null>(null);
const isLoading = useSelector(s => s.loading);
// 错误
const list = useState(...)[0];   // 无意义命名
说明：布尔状态用 is/has/can 前缀（如 isLoading、hasData）。

3.5 常量命名（UPPER_SNAKE_CASE）

// 正确：模块级常量全大写 + 下划线
const WATER_CLASS_LABELS = {...};
const MAX_WELL_COUNT = 1000;
// 错误
const waterClassLabels = {...};   // 模块级常量误用 camelCase

3.6 类型与接口命名（PascalCase）

// 正确
interface WellNetworkProps { ... }
type WaterQualityClass = 1 | 2 | 3 | 4 | 5;
// 错误
interface wellNetworkProps { ... }   // 首字母小写

3.7 函数命名（动词 + 名词，camelCase）

// 计算类：calc + 对象
calcBalance(input);
// 获取类：get/query + 对象

// 分类/判定类：classify + 对象
classifyFactor(value, factor);

generateWellReport(well, options);

// 错误

3.9 命名一致性检查

  • 组件/类型：PascalCase
  • Hook/变量/函数：camelCase
  • 模块级常量：UPPER_SNAKE_CASE
  • Hook 均以 use 开头
  • 测试文件与源文件同名
