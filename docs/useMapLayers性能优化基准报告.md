# useMapLayers 图层渲染性能优化基准报告

> 项目：河北省地下水环境信息平台（hebei-groundwater-platform）
> 文件：`src/pages/useMapLayers.ts`（优化后）/ `src/__tests__/bench/useMapLayers.legacy.ts`（优化前，提取自 git `72f09a5^`）
> 基准脚本：`src/__tests__/mapview-benchmark.test.ts`
> 生成日期：2026-08-19
> 质量基线：tsc 0 / ESLint 0 / Vitest 1112/1112

---

## 一、背景与目的

`useMapLayers` 负责空间地图页 8 类图层（标注、区划、省界、县级覆盖、超采区、资源量、水源地POI、岩溶泉POI）的 Leaflet 渲染。在重构（拆分 MapView）后，对其做了一轮性能优化，核心三点：

1. **依赖拆细**：各 `useEffect` 的依赖由「整个 `activeLayers` Set」改为「该图层关心的布尔派生值」（如 `markersVisible`、`overdraftVisible`），切换无关图层时不再触发该图层的整层重建，**消除连锁重建**。
2. **数据 useMemo 缓存**：`getVisibleMarkers` 过滤结果、`overdraftPolygons.filter` 结果、县级覆盖计算（`buildCountyCoverageSpecs`）仅在真实输入变化时重算。
3. **popup HTML 与图标预计算**：marker 的 `divIcon` 与 `buildMarkerPopup` HTML 缓存为 `MarkerSpecs`，图层反复开关时复用缓存，不重复拼接。

本报告通过基准脚本对比优化前后在**综合场景 + 4 个极端操作场景**下的重建开销，量化优化效果，并作为回归防线。

---

## 二、基准方法

- 通过 `renderHook` 在 jsdom 环境分别渲染优化前（legacy）与优化后（optimized）的 `useMapLayers`。
- 用 `vi.mock` 拦截 `buildMarkerPopup`（popup HTML 拼接）与 `getVisibleMarkers`（可见标注计算）进行计数；各图层组 ref 的 `clearLayers` 调用次数即该图层的整层重建次数。
- 对两套实现执行**完全相同的操作序列**，统计各图层重建次数、popup 拼接次数、可见标注计算次数。

### 指标说明

| 指标 | 含义 |
|---|---|
| 各图层 `clearLayers` 次数 | 该图层的整层重建次数（每重建一次，Leaflet 会 clear + 重新 add 全部子图层） |
| 合计重建次数（totalClear） | 所有图层重建次数之和，反映整体渲染开销 |
| popup 拼接次数（buildMarkerPopup） | marker 弹窗 HTML 字符串拼接次数，反映 DOM 字符串生成开销 |
| 可见计算次数（getVisibleMarkers） | 可见标注数组过滤计算次数 |

## 三、场景定义

| 场景 | 操作 | 优化预期 |
|---|---|---|
| S0 综合 | 10 次图层切换（开关多种图层 + 改可见类别） | 显著提升（连锁重建消除） |
| S1 极端 | markers 单图层开关 ×20 | 显著提升（连锁消除 + popup 缓存） |
| S2 极端 | 可见标注类别切换 ×20 | 无回归（必要重建） |
| S3 极端 | 超采区过滤切换 ×20 | 无回归（必要重建） |
| S4 极端 | 全图层极速开关 ×20 | 显著提升（连锁消除最明显） |

## 五、结论

1. **优化发力的场景（S0 / S1 / S4）均实现显著下降**：
   - 整层重建总次数：↓ 38% ~ 72%
   - popup HTML 拼接：↓ 81% ~ 95%
   - 可见标注计算：↓ 80% ~ 95%
2. **连锁重建被彻底消除**：极端场景 S1/S4 中，某一图层反复操作时，其余无关图层从每次重建降到 1 次（标注图层从被牵连 21 次降到 1 次）。
3. **必要重建场景（S2 / S3）无回归**：优化前后行为一致，缓存与依赖拆细未引入功能差异或副作用。
4. **性能提升主要在交互侧**：图层切换、图层开关等高频操作不再触发全量图层重建，地图页在快速操作时明显更流畅。

## 六、复现方式

```bash
# 仅运行性能基准（需 Node + npm 环境）
npx vitest run src/__tests__/mapview-benchmark.test.ts

# 运行全部测试
npx vitest run
```

基准脚本内置断言：
- `assertImproved`（S0/S1/S4）：优化后合计重建必须严格小于优化前。
- `assertNoRegression`（S2/S3）：优化后各项不劣于优化前。

未来若修改 `useMapLayers` 渲染逻辑，可据此快速确认性能未退化。
