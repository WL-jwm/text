## 2. 排查清单

### 2.1 代码审查清单

#### A. 空集合崩溃（模式 A）

在以下操作前，确认集合是否可能为空：

```typescript
// 高危操作清单
Math.max(...arr)     // 空数组返回 -Infinity
Math.min(...arr)     // 空数组返回 Infinity
arr.reduce(fn, init) // 空数组无初始值时报错
arr[0]               // 空数组返回 undefined
arr.map(fn)[0]       // 链式调用未判空
```

**排查问题：**
- [ ] 该数组是否可能为空？
- [ ] 空数组时是否有默认值/提前返回？
- [ ] 链式调用中每一步是否都有空值保护？
- [ ] 对象属性访问是否用了 `?.` 安全链？

#### B. 循环累加停滞（模式 B）

在遍历并累加类别/等级的循环中：

```typescript
// 危险信号
for (const item of list) {
  if (condition) {
    result = item;      // 设为当前项而非下一项
  }
}
```

**排查问题：**
- [ ] 循环变量是推进到"下一项"还是停留在"当前项"？
- [ ] 满足条件后是否应该 `break`？
- [ ] 最后一次迭代是否产生正确的边界结果？
- [ ] 是否有测试验证多级累加场景？

#### C. 边界条件过严（模式 C）

```typescript
// 危险信号
if (lines.length < 2) return empty;  // 阈值 2 是否合理？
if (data.length < 3) return null;    // 阈值 3 是否合理？
```

**排查问题：**
- [ ] 该阈值的最小合理值是多少？
- [ ] 边界值（threshold-1, threshold, threshold+1）各应返回什么？
- [ ] 拒绝输入时是否丢失了有价值的中间结果（如表头信息）？

### 2.2 测试审查清单

#### D. 测试数据失配（模式 D）

**时间相关：**
- [ ] 测试中的时间戳是硬编码还是动态计算？
- [ ] 硬编码时间戳是否超过过滤窗口（如 24h）？
- [ ] 测试是否在未来的任何日期都能通过？

**Mock 数据与逻辑匹配：**
- [ ] Mock 数据是否满足被测函数的**所有**前置条件？
- [ ] 条件分支（if/else）的每个路径是否都有对应的 mock 数据？
- [ ] 算术比较（如 `>= 3.5`）的边界值是否在 mock 中覆盖？

**断言方向：**
- [ ] 比较操作符方向是否正确（`>` vs `<`）？
- [ ] 预期值是否与注释/文档一致？
- [ ] 测试失败时的错误信息是否能直接定位问题？

## 3. 修复模板

### 3.1 空集合崩溃模板

```typescript
// 修复前
function processData(items: Item[]) {
  const max = Math.max(...items.map(i => i.value));
  // 当 items 为空时，max = -Infinity，后续访问崩溃
  return LABELS[max].name;
}

// 修复后
function processData(items: Item[]) {
  if (items.length === 0) {
    return { class: 0, label: '无数据' };  // 提前返回默认值
  }
  const max = Math.max(...items.map(i => i.value));
  return {
    class: max,
    label: LABELS[max]?.name ?? '未知',  // 安全链
  };
}
```

**适用场景：** 数组筛选/聚合后可能为空、对象属性可能缺失、链式调用

### 3.2 循环累加模板

```typescript
// 修复前
for (const level of LEVELS) {
  if (value > level.threshold) {
    result = level;           // 设为当前级，不累加
  }
}

// 修复后
for (let i = 0; i < LEVELS.length; i++) {
  if (value > LEVELS[i].threshold) {
    if (i + 1 < LEVELS.length) {
      result = LEVELS[i + 1];  // 设为下一级，推进累加
    } else {
      result = LEVELS[i];      // 末级边界
    }
  } else {
    break;                     // 未超过 → 停止
  }
}
```

**适用场景：** 水质分类、等级评定、梯度定价、分层阈值判定

### 3.4 测试数据时间戳模板

```typescript
// 修复前（硬编码，随时间失效）
const mockAlerts = [
```

## 4. 测试编写规范

### 4.1 边界值三件套

每个边界值应覆盖三个点：

```typescript
describe('阈值边界', () => {
  it('恰好等于限值应归入当前类', () => { /* threshold */ });
  it('略低于限值应归入当前类', () => { /* threshold - epsilon */ });
  it('略高于限值应归入下一类', () => { /* threshold + epsilon */ });
});
```

### 4.2 空值覆盖

```typescript
describe('空值处理', () => {
  it('空数组返回默认值', () => { /* [] */ });
  it('undefined 值被跳过', () => { /* { key: undefined } */ });
  it('全部为 undefined 仍返回有效结果', () => { /* */ });
  it('null 值不崩溃', () => { /* null */ });
});
```

### 4.3 时间无关性

```typescript
// 好的测试：不依赖固定时间
const today = new Date();
const ts = today.toISOString();

// 坏的测试：依赖固定时间
const ts = '2026-08-07T10:00:00';
```

### 4.4 Mock 数据完整性

```typescript
// 检查 Mock 数据是否满足所有前置条件

// 确认 Mock 数据确实触发了目标代码路径
```

## 5. 预防措施

### 5.1 代码审查检查项

提交 PR 前逐项检查：

```
□ 所有 Math.max/min 操作前确认数组非空
□ 循环累加逻辑使用 nextIdx 而非 currentIdx
□ 输入校验阈值设为最小必要值（优先用 === 0 而非 < 2）
□ 对象属性访问链全部使用 ?. 安全链
□ 条件分支的每个路径都有对应的测试覆盖
```

### 5.2 测试检查项

```
□ 测试时间戳使用动态计算
□ Mock 数据满足所有前置条件
□ 断言方向与注释一致
□ 边界值（threshold-1, threshold, threshold+1）全覆盖
□ 空数组/空对象/undefined/null 各有一条测试
```

### 5.3 新增函数模板

```typescript
export function safeProcess(input: InputType): ResultType {
  // 1. 空值提前返回
  if (!input || input.length === 0) {
    return DEFAULT_RESULT;
  }

  // 2. 边界检查
  if (input.length < MIN_REQUIRED) {
    return PARTIAL_RESULT;  // 返回部分结果而非空
  }

  // 3. 核心逻辑（带安全链）
  const result = input.map(item => {
    return {
      value: item.value,
      label: LABELS[item.class]?.label ?? '未知',
    };
  });

  return result;
}
```
